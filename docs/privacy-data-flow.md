# Privacy data flow

For analysis, the server receives a public Facebook URL, fetches public metadata and identity-scoped embedded media fields, then sends a validated Facebook video or its thumbnail plus bounded title/description to Google Gemini. Small videos are sent inline. Larger supported videos are streamed to Gemini Files API; deletion is attempted after analysis and after processing failure once the remote file name is known. Cleanup errors are logged without file URLs or credentials. Provider-side retention still applies and deletion is not guaranteed during network failure. Direct video URLs and media bytes are not stored in D1. Thumbnail URLs (which may contain CDN signatures), source URLs and recipe results are stored in the short-lived cache and saved recipe records. Account data is not sent to Gemini.

For accounts, D1 stores the username, the email address, a PBKDF2 password hash with its salt and iteration count, and a verification timestamp. The plaintext password is never stored or logged. Sessions and reset/verification tokens are stored only as SHA-256 digests. The email address is used for password reset and verification only; it is passed to the email provider (Resend) when such a message is sent, and is never written to logs.

For saved recipes, the server derives an HMAC owner key from the user id with `USER_ID_PEPPER`; D1 stores that key, recipe content, public source URL, remote image URL and timestamps. The app does not persist image bytes.

Users should be told that image content is processed by Google and that AI cooking instructions are estimates. Deletion removes the saved D1 row owned by that user. There is no self-service account deletion yet, so removing an account is currently a manual database operation.

Cache entries have a 30-minute logical lifetime. Sessions expire after 30 days; reset tokens after 60 minutes and verification tokens after 24 hours. Expired rows are removed opportunistically in bounded batches while the Worker receives traffic, not on an exact deletion SLA. Rate-limit keys are SHA-256 digests (pseudonymous, not anonymous) rather than raw IP/email/username values. Saved recipes remain until deleted. See the operator deletion and retention procedures in the release runbook.
